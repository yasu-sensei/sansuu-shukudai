# GASへの配置・検証手順（第2段階）

この段階で用意したのはHTML配信です。Googleアカウントによる児童本人確認、教師の権限管理、スプレッドシート保存はまだ有効になりません。現在の学習記録はGAS版でもブラウザ内保存です。本番運用や実児童データでの利用は認証・保存処理の実装後に行います。

## 生成

Node.js 22.12以上とnpmを使用します。

```sh
npm ci
npm run build:gas
```

出力は `build/gas/Index.html`、`Code.gs`、`appsscript.json` の3ファイルです。ビルド時にGoogleへの接続、Googleログイン、デプロイは行いません。出題・採点などは通常版と同じソースから生成します。

## 学校アカウントの検証用プロジェクトへ配置

1. 学校のGoogleアカウントでApps Scriptの新規テストプロジェクトを作成します。管理者がApps Scriptを制限している場合は、学校の管理者へ利用可否を確認します。
2. `Code.gs` に生成した `build/gas/Code.gs` を貼り付けます。
3. HTMLファイルを **Index** という名前で作成し、生成した `Index.html` の全内容を貼り付けます。
4. プロジェクト設定でマニフェスト表示を有効にし、`appsscript.json` を生成物と一致させます。V8、日本時間が指定されています。
5. 開発者本人だけが利用できるテスト用デプロイで表示を確認します。全員・匿名向けには公開せず、学校環境の利用制限を維持します。利用可能なデプロイ設定は学校の管理ポリシーに従います。
6. テスト用のクラス・番号で、ログイン、カレンダー、自由練習、正誤表示、中断、宿題完了を確認します。GAS版のデータは元の静的ページと同じ保存領域とは限らず、既存記録は自動移行されません。

CSSやJavaScriptの別ファイルをGASエディターへ個別に登録する必要はありません。生成済みHTMLに含まれています。`src/` のJavaScriptを直接貼り付けると、相対importが解決しないため動きません。変更後は再ビルドして貼り直し、検証用デプロイの内容も更新してください。

## 学校Googleアカウントを使う認証の方針

学校Googleアカウントが利用可能であることは確認済みです。次段階で、アカウントと内部児童IDをサーバー側で対応付けます。画面から送ったメールアドレスやクラス・番号だけを信用しません。

GASの「次のユーザーとして実行」「アクセスできるユーザー」の組み合わせにより、取得できる利用者情報やスプレッドシートの権限が変わります。`Session.getActiveUser().getEmail()` は設定によって空文字になる場合があるため、まず学校の実アカウントで教師・児童を識別できるか確認します。識別できない場合はログイン成功にせず、公開・実行方式を見直します。児童へシートを直接共有することを回避策にしません。

次段階の着手時に確認する情報は、学校Workspaceのドメイン、学校管理者によるApps Script・Webアプリの利用可否、児童アカウントと名簿の対応管理方法です。パスワードや認証トークンをチャット・リポジトリに記載する必要はありません。

## 自動検証の範囲

- 元HTMLのSHA-256、HTML要素、CSSを確認。
- 分離後の出題列を元実装と50,000問比較。
- 通常版とGAS向け生成HTMLで同じ16シナリオを実ブラウザ実行。
- ビルドの再現性、JS/CSSの同梱、`doGet` の出力設定を検証。

GAS向けHTMLのブラウザテストはローカルHTTP配信です。Googleの実際のHTML Service、iframe内のストレージ制限、学校タブレット、本人確認や権限は別途実環境で検証する必要があります。クラウド環境から学校のGASへデプロイしたことを意味しません。

# 学校用GASの設定・検証手順

実装した学校用モードは、児童の初回登録、学校アカウント照合、先生の名簿修正・宿題一括配信・取り組み状況・支援目安を備えています。初回登録は児童自身が確認して行うため、児童メールの事前登録は不要です。ガチャ・図鑑はまだ統合していません。

実際の学校Workspaceでのデプロイ・本人識別・端末ストレージ・同時利用は未検証です。この手順でテスト用の記録から確認してから運用してください。

## 1. 配信用ファイルを用意する

```sh
npm ci
npm run build:gas
```

`build/gas/` に次の5ファイルを生成します。Googleへの接続や自動公開は行いません。

| ファイル | 用途 |
| --- | --- |
| `Index.html` | 児童画面。CSS・JSを同梱 |
| `Teacher.html` | 先生画面。CSS・JSを同梱 |
| `Code.gs` | 学校アカウントの取得、認証、API、イベント保存 |
| `ClassroomCore.gs` | サーバーでの出題・再採点・名簿・宿題・集計 |
| `appsscript.json` | V8、日本時間、メール識別・シートアクセスのスコープ |

GitHub Actionsでテストが成功した場合は、Actionsの実行結果から `gas-school-package` アーティファクトをダウンロードする方法もあります。アーティファクトは一時保管です。ソースと生成手順はGitHubに残ります。

## 2. 学校アカウントで保存先とプロジェクトを作る

1. 先生の学校Googleアカウントで、テスト用の空のスプレッドシートを作成します。児童には共有しません。
2. 同じ学校アカウントでApps Scriptプロジェクトを作成します。
3. `Code.gs`、`ClassroomCore.gs`、HTMLファイル **Index** と **Teacher** を作り、対応する生成ファイルの内容を貼り付けます。拡張子はエディターが付けます。
4. プロジェクト設定でマニフェスト表示を有効にし、生成した `appsscript.json` を反映します。
5. プロジェクト設定の「スクリプト プロパティ」に次を設定します。値をGitHubやチャットへ書く必要はありません。

| プロパティ | 設定内容 |
| --- | --- |
| `SCHOOL_DOMAIN` | 学校Googleアカウントのメールの@以降。`@`は含めない |
| `SCHOOL_YEAR` | 年度を4桁で指定。例：`2026` |
| `TEACHER_EMAILS` | 操作を許可する先生の学校メール。複数はカンマ区切り |
| `CLASSROOM_SPREADSHEET_ID` | テスト用スプレッドシートのURLの `/d/` と次の `/` の間 |

6. エディターで `initializeClassroom` を先生本人の学校アカウントとして実行し、必要な権限を承認します。`ClassroomEvents` シートを作成します。再実行しても既存の記録を消しません。

## 3. 学校内のテスト用Webアプリとして配置する

- まず先生本人だけで開けるテスト用デプロイで画面と設定を確認します。
- 児童アカウントを試す段階では、学校ドメイン内の利用に限定し、シートへ書き込める教師／デプロイ所有者の権限で実行する構成を学校管理者と確認します。シートを児童へ直接共有しません。
- **`Session.getActiveUser().getEmail()` で実際の児童メールを取得できることを必ず確認します。** 同じ学校ドメインでも、管理ポリシー・公開設定・実行設定によって空文字になる場合があります。この場合、アプリはログインを拒否します。デプロイ所有者のメールに置き換える動作や、番号だけで認証を通す動作はありません。
- 空文字になる環境では、この構成で運用を開始せず、管理者と学校内の本人認証方式を調整してください。「アクセスしているユーザーとして実行」へ変更するだけではシート権限の問題を解決できないため、児童へシート共有する回避策は使いません。
- 全員・匿名向けには公開しません。Googleのログイン・承認画面が必要な場合は学校の方針に従って行います。
- 学級共通のGoogleアカウントでは児童を区別できません。1人ずつ自分の学校アカウントで開いてください。

## 4. 初回登録と先生の確認

- 児童は共通のWebアプリURLを開き、学級・番号を選びます。
- 初回は、**学校メール・学級・番号・登録後は先生しか直せないこと**を確認画面で表示します。確認チェックを入れるまで登録できません。
- 確定すると、アクセス中のGoogleアカウントをサーバーが取得して登録します。ブラウザから送られた別のメールアドレスは採用しません。
- 同じメールは1人分のみ、有効な同じ学級・番号は1人分のみ登録できます。登録済み番号への上書きは拒否します。
- **事前名簿なしでは、最初に選んだ番号が本人の番号かは自動判定できません。** 初回は先生の見守りの下で登録し、先生画面で対応を確認してください。重複・誤登録は先生が修正します。
- 名前は自動取得しません。名簿は学校メール・学級・番号で完成し、必要な場合は先生が名前を追記できます。
- 登録後は選んだ学級・番号と本人アカウントの登録が一致する場合だけ利用できます。児童自身で登録内容を変更できません。

先生画面は同じWebアプリURLの末尾に `?view=teacher` を付けます。先生アカウントで児童画面を開いた場合にも、管理画面への入口を表示します。

## 5. 名簿修正用の暗証番号

- 先生画面から最初に6〜12桁の暗証番号を設定します。先生アカウントの許可リストに含まれる本人だけが設定できます。
- 学級・番号・メール・有効状態の修正時は、その児童の実行中の学習を中断扱いにし、新しい登録内容で選び直してもらいます。
- 登録後の学級・番号・メール・名前・有効状態を変更する際は、**先生のGoogleアカウントと暗証番号の両方**をサーバーが確認します。初回の児童登録に暗証番号は不要です。
- 暗証番号はソルト付きSHA-256でスクリプトプロパティに保存し、原文は名簿・履歴・HTML・localStorageへ保存しません。
- 連続5回失敗すると、その先生アカウントによる暗証番号の確認を15分間停止します。
- 暗証番号変更には現在の暗証番号も必要です。変更操作の応答だけが失われた場合は、一度画面を更新し、新しく入力した番号で確認してください。
- 忘れた場合はプロジェクト管理者がスクリプトプロパティの `TEACHER_PIN_HASH` と `TEACHER_PIN_SALT` だけを削除し、先生画面で再設定します。`ClassroomEvents` の削除や初期化は不要です。

## 6. 先生画面でできること

- 名簿の確認、暗証番号付きの個別修正、必要な場合のタブ区切り一括修正。
- 1〜4組から複数選択し、最大31日分の宿題を同じモードで配信。土日を除く設定あり。
- 開始済みの宿題のモードは変更不可。同じ日に同じモードを再配信しても宿題は増えません。
- 表示期間・学級を選んで「未着手・取り組み中・中断・完了」、最初の2分の正解／回答、時間、獲得ポイントを確認。
- 各モードの目安を設定。空欄は「未設定」。直近3回の完了記録で、2回以上目安未満なら「ようすを確認」。3回未満は「記録不足」。期間フィルターには左右されません。
- 評価や順位は児童画面には出しません。目安と同じ正解数は「目安以上」です。
- 目安は教育上の標準値をアプリが断定するものではなく、先生が授業に合わせて設定します。

## 7. 保存・復旧・運用上の確認

- 正本はスプレッドシートの `ClassroomEvents` です。1操作を1行で確定し、名簿・宿題・セッション・完了・残高・付与済みボーナスをそこから復元します。操作した学校メールも記録します。直接行を編集・削除しないでください。
- 同時処理はScriptLockで制御します。応答を失った場合も同じ操作IDを再送し、同じ完了に二重加算しません。
- 児童は開始時、5回答ごと、15秒ごと、完了・中断時に保存を行います。自由練習は保存・ポイント付与の対象外です。
- 完了画面の花丸・ポイントはサーバーで確定後に表示します。通信失敗時は画面を閉じず「もういちど ほぞんする」を押してください。更新・タブを閉じる操作では未送信の記録を復旧できません。最後に保存できたところまでが残ります。
- 通信が5分以上途絶えたセッションは先生画面で中断扱いにします。「取り組み中」は、その時点までの通信記録であり、端末を実際に見ていることの保証ではありません。
- サーバーは発行した出題列を再生し、回答順・再回答・正誤・回答間隔・120秒条件・倍率・ボーナスを再計算します。端末の集計ポイントは採用しません。ただし、通信遅延を伴う端末経過時間の完全な証明や、人間が解いたことの証明はできません。
- 端末を変更するための移行・引継ぎ専用機能は作りません。先生の確認とポイント整合性のため、学校用の記録はサーバーに保存します。
- 1イベントの長さは45,000文字までです。長い名簿を一括修正すると上限に達する場合は分割してください。
- 年度ごとに別の保存先シート／プロジェクトを使用します。既存ログを残したまま年度プロパティだけを変更する運用は対象外です。
- 現段階はイベントログ全体を読み直す方式です。140人の同時開始・履歴の増加、GASの実行制限、シートの読み書き時間は実学校で検証が必要です。まず少人数で確認し、必要に応じて集計の保存や索引を追加します。

## 自動テストと未実施のこと

自動テストは実際のサーバーロジックとGASアダプターを模擬サービスで実行し、両配信形式のブラウザ操作も検証します。Google本番へのデプロイ、実Workspaceのメール取得・権限、実際のシート障害、学校タブレット、同時140人の負荷を検証したことにはなりません。これらは上記設定後の確認が必要です。


### 先生のアカウントで児童操作をテストする

先生も共通URLからクラス・番号を選び、確認チェック後にテスト登録できます。
先生の管理権限は維持され、名簿には「先生（テスト）」として表示されます。
実際の児童が使わない空き番号を選んでください（例：3組35番）。登録済みの番号は上書きできません。
テストも通常の名簿と学習記録に保存され、同じ学級に配信した宿題でポイントまで確認できます。
番号変更や無効化には管理画面と先生の暗証番号が必要です。
実際の児童のGoogleアカウント取得・管理画面の拒否は、児童用アカウントでも別途確認してください。

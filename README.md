# さんすうしゅくだい

小学1年生がタブレットで使う算数宿題ゲームの試作版です。現在は静的HTMLだけで動作し、記録は同じブラウザの `localStorage` に保存されます。GAS向けの配信ファイル生成と `doGet` を用意しています。学校Googleアカウントを使う方針ですが、認証・スプレッドシート連携・ガチャ・図鑑はまだ実装していません。

## 起動

Python 3で静的ファイルを配信します。アプリ本体にnpm依存関係やビルドはありません。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

ルートの `index.html` が入口です。CSSは `src/client/styles.css`、画面処理は `src/client/game.mjs`、出題・完了・ポイント・連続ボーナスは `src/domain/` に分離しています。ブラウザがES Modulesを読み込むため、HTMLの直接ファイル起動ではなくHTTPサーバーを使ってください。

従来の `homework_math_calendar_keypad_practice_v10.html` は変更せず保持しています。HTML要素とCSSの一致、および同じ乱数による出題列の一致をテストし、見た目・操作・出題ルールを維持します。

## テスト環境

必要なものはNode.js 22.12以上、npm、Python 3、Chromiumです。

```sh
npm ci
npm run test:install
npm test
```

LinuxでブラウザのOS依存パッケージも必要な場合は `npx playwright install --with-deps chromium` を実行してください。OSパッケージの導入には管理権限が必要な場合があります。

既存のChromiumを使う環境では、ブラウザのダウンロードを省略できます。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm test
```

- `npm run test:unit`: 分離した本番モジュールを直接読み込み、出題・ボーナス・完了・ポイント・GAS配信物をNode.jsで検証。
- `npm run test:e2e`: 通常版 `index.html` とGAS向け `build/gas/Index.html` の両方をChromiumで操作。専用の静的サーバーをポート8765で起動・終了。GAS用ビルドは自動実行します。
- 時刻は日本時間に固定し、Playwright Clockで仮想時間を進めます。実時間で2分待ちません。
- E2Eは各テストで独立したブラウザコンテキストを使います。通常利用の学習記録を操作しません。
- 失敗時のトレースは `test-results/` に出力します。`npx playwright show-trace <trace.zipのパス>` で確認できます。
- GitHub Actionsでも単体テストとブラウザテストを実行する設定を用意しています。

通常のモジュール読み込みで本番ロジックをテストします。元HTMLからの抽出アダプターは変更前の比較基準としてのみ使用し、全5モード×100シード×100問について問題順序・式・答えの完全一致を確認します。元HTMLのSHA-256も固定しています。

## 現在の画面・操作

1. 1〜4組、1〜35番から選び、確認画面で利用者を確定します。
2. カレンダーの日付を押して宿題を開始します。今日以前の設定済み宿題が対象です。
3. 大きなテンキーで入力し、「こたえる！」で送信します。空欄は送信されません。
4. 完了すると花丸と獲得ポイントを表示します。完了済みの宿題は再挑戦できません。
5. 自由練習では好きなモードを選べます。宿題記録やポイントには影響しません。

解答欄は固定サイズで、正答は◯、誤答は✕を表示します。正答後650ms、誤答後900msは回答を受け付けません。中断は確認ダイアログを経て行います。

## 出題仕様

| モードID | モード | 1セットの構成 | ポイント倍率 |
| --- | --- | --- | --- |
| 0 | 10までのたしひき | 答え0〜10を各1回、11問。両方の数は0〜10 | 1 |
| 1 | 20までのくりあがりたしざん | 答え11〜18を各1回、8問。両方の数は1〜9 | 2 |
| 2 | 20までのくりさがりひきざん | 答え2〜9を各1回、8問。11〜18から2〜9を引き、繰り下がりが発生する式 | 2 |
| 3 | 九九① | 1・2・3・5・9の段から各2問、10問 | 2 |
| 4 | 九九② | 4・6・7・8・9・10の段から各2問、12問 | 3 |

- 九九で掛ける数は1〜9です。九九②の「10の段」も現行仕様として維持します。
- 「20まで」という表示でも、足し算で答え19・20は出ません。
- セット内の順序はランダムです。足し引きではセット境界で同じ答えが続かないようにします。
- たしひきでは足し算・引き算の数の偏りを抑えます。
- 直近35問と同じ式、同じセットで使用済みの式の優先度を下げます。
- 九九では同じ段が続きにくいよう並べ替えますが、連続を完全に禁止する保証はありません。
- 誤答1回目は同じ問題に再回答、2回目の誤答で次の問題へ進みます。再回答で正解した場合も正解数は1増えます。
- 回答数は送信回数です。再回答もそれぞれ1回と数えます。

## 完了・ポイント仕様

宿題は **経過120秒以上、かつ合計10問以上正解** で完了します。10問正解しても120秒未満では終了せず、120秒時点で9問以下なら10問正解まで続きます。

```text
基本ポイント = 最初の120秒未満の正解数 × モード倍率 + 完了ボーナス10
```

120秒ちょうど以降の解答は、完了判定用の合計には含みますが、最初の2分間の回答数・正解数には含みません。正誤表示の待ち時間も経過時間に含まれ、表示中は完了処理を待ちます。完了確認は150ms間隔の更新処理、または正誤表示後に行われます。

自由練習は120秒以上で終了し、10問正解は不要です。正誤表示中なら終了を待ちます。ポイント、宿題完了記録、ボーナス付与済み情報は変更しません。中断した宿題にもポイントは付きません。

### 連続ボーナス

暦の連続日数ではなく、日付順の「設定済み宿題」の連続完了数です。宿題のない日は連続を切らず、未完了の宿題で切れます。

| 連続完了数 | ボーナス |
| --- | --- |
| 3 | 20ポイント |
| 5 | 30ポイント |
| 10 | 50ポイント |
| 20、30、40… | 各50ポイント |

過去の宿題を後から完了すると、複数の節目にまとめて到達する場合があります。同じ「宿題日付＋連続数」の付与は一度だけです。完了記録の `earned` は基本ポイントであり、連続ボーナスは `claimed` に別途保存します。結果画面の獲得ポイントにはその回に発生した連続ボーナスも含みます。

## 保存データ

| localStorageキー | 内容 |
| --- | --- |
| `math-homework-v2:identity` | 確定したクラス・番号 |
| `math-homework-v2:schedule` | 日付からモードIDへの対応。現在はクラス別ではなくブラウザ内共通 |
| `math-homework-v2:<クラス・番号>` | `records`（日付別完了記録）、`claimed`（付与済みボーナス）、`points`（ポイント） |

完了記録には `mode`、`firstCorrect`、`firstTotal`、`correct`、`total`、`elapsed`（丸めた秒数）、`earned`、`completedAt` が含まれます。途中経過・自由練習・問題別履歴は保存しません。初回は直近8日間のうち平日にデモ宿題を設定します。

## 現時点の制約・未解決事項

- クラス・番号の選択は本人認証ではありません。教師用暗証番号もクライアント側にある試作用です。
- 記録とポイントはブラウザ内で編集可能です。本番の残高・権限の根拠には使えません。
- 別端末への引継ぎ、バックアップ、GASの保存APIは未実装です。GAS配信だけでは認証・端末間同期は有効になりません。
- 未来の宿題は設定されていても児童画面では宿題なしの表示です。
- 保存済み利用者だけが残り宿題データがない場合、デモ宿題生成より先に描画されます。
- 過去の宿題追加・削除によって連続ボーナスの並び・付与結果が変わる可能性があります。本番での改訂・訂正方針が必要です。
- 仮想時間のChromiumテストは、実タブレット、Safari、スリープ復帰、通信遅延の検証を代替しません。
- HTML要素とCSSは元HTMLとの一致を検証しています。実機での画像比較は未導入です。

## GAS向けビルド

```sh
npm run build:gas
```

`build/gas/` に `Index.html`（CSS・JavaScriptを同梱）、`Code.gs`、`appsscript.json` を生成します。相対パスによるJS/CSS読込やES Modulesを必要としないHTMLになるため、HTML Serviceへ配置できます。生成物はGit管理せず、ソースから再生成します。このコマンドはGoogleへ接続・公開しません。

GASエディターへの配置方法と学校アカウントに関する注意は [docs/gas-setup.md](docs/gas-setup.md) を参照してください。クラウド環境では配信物のローカルブラウザ動作と `doGet` の模擬実行を検証し、実際のGoogle環境へのデプロイは未実施です。

## 開発予定

1. 仕様固定とテスト整備（第1段階で完了）：元HTML保持、入口追加、出題・完了・ポイントの回帰テスト。
2. **GAS配信準備と役割分離（今回）**：CSS・出題・採点ルールを分離し、GAS配信物を生成。保存・通信の切替は次段階。
3. 教師・児童認証、1〜4組への日付・モード別宿題一括設定、児童別カレンダー。
4. サーバー側での採点検証、学習記録、ポイント台帳、別端末への引継ぎ。
5. ガチャ・図鑑の統合と通信切断・同時実行時の復旧。
6. タブレット実機・同時利用・年度更新などの運用検証。

ガチャの確定要件は1回100ポイント、通常30種類で合計90%、シークレット2種類で合計10%、ノーマル→ゴールド→レインボーへの進化です。最終進化済みは排出対象から外し、一方のグループが全種類最終進化したら残るグループから排出します。図鑑は獲得済みのみ表示し、画像は別途提供予定です。残高・履歴・進化はGAS側で管理します。全32種類完成時の扱い、進化に必要な獲得枚数、グループ内の抽選確率は実装前に明文化します。

GAS向け構成とデータの提案は [docs/gas-architecture.md](docs/gas-architecture.md) を参照してください。
